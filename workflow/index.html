Building an AI-assisted design workflow

From interface designs to working interactions and implementation starting points.

Workflow developmentSeptember 2026–present

ContextProblemProcessSolutionImpact

Context

At Modirum Platforms, I work primarily as the sole designer for NSC3, a situational-awareness and critical-communications platform. I follow discussion about how AI is changing UX design, and was given time and resources to develop how we use it in our design and development work.

Problem

Covering a feature’s flows and states meant creating and maintaining a large number of screens in Figma. When a design review identified changes, I had to revise those screens and go through them again before developers could see what needed adjusting.

This could interrupt other priorities while the feature was already being developed or partly implemented. Developers then had to compare the revised designs with the implementation to work out the differences.

I wanted to keep Figma for defining layouts, while moving more of the detailed states and interactions into working code. For coding agents to build interfaces that fit NSC3, they also needed clear guidance on NSC3’s design conventions.

Process

Starting with a delivery pilot

My first practical pilot came during preparations for a targeted alerting customer demo. Developers wouldn’t have time to implement the required recipient-facing LiveLink, so I volunteered to build it. I directed AI to implement my designs in the product codebase and checked the behaviour locally. Our Web developer reviewed the code and made last-minute fixes before it was merged and delivered for the customer demo.

Establishing a reusable approach

I later used Alpha Design Partners’ AI-native design maturity framework to structure the next steps. I aligned Figma variables with code tokens and added repository guidance for coding agents. These shared rules support NSC3 Web development as well as prototypes.

I established a dedicated prototyping environment within the development codebase, using actual components, fictional data and simulated services.

I design the minimum UI needed for the feature in Figma, then direct AI to build an interactive code prototype. In the prototype, I add states, interactions and responsiveness, and demonstrate the flows. I apply review feedback directly to the prototype, where the team can examine the revised behaviour. Prototype code can then provide a starting point for developers to review and adapt for implementation.

Solution

The workflow in practice: Event image viewer.

Operators use the viewer to examine images associated with an Event, such as a detection requiring their attention. The design needed to support closer inspection while retaining the Event details and navigation between images.

I used Figma to establish the layout and a coded prototype to refine zooming, panning and behaviour at narrower window sizes. I completed the design and prototype on the same day, then reviewed the interaction with our Web developer.

Impact

The LiveLink pilot reached the customer POC after developer review and corrections. The subsequent prototyping environment has been used by the scrum team for design reviews, bringing working interactions into the discussion.

Our Web developer used the image-viewer prototype code as a starting point for implementation, describing it as mostly usable as is.

The workflow has been used for a few features so far. It gives me a way to refine behaviour in code and provide a concrete starting point for engineering, alongside the interface layouts in Figma.
