Building an AI-assisted design workflow

ContextProblemProcessSolutionImpact

Context

At Modirum Platforms, I work primarily as the sole designer for NSC3, a situational-awareness and critical-communications platform. Alongside designing new features, I wanted to make better use of AI in my design process and help kickstart development.

Problem

Covering a feature’s flows and states meant creating and maintaining a large number of screens in Figma. When a design review identified changes, I had to revise those screens and go through them again before developers could see what needed adjusting.

This could interrupt other priorities while the feature was already being developed or partly implemented. Developers then had to compare the revised designs with the implementation to work out the differences.

I wanted to keep Figma for defining layouts, while moving more of the detailed states and interactions into working code. For coding agents to build interfaces that fit NSC3, they also needed clear guidance on NSC3’s design conventions.

Process

Starting with a delivery pilot

I was shaping the idea of prototyping in code during the events design work, and had discussed it with my supervisor. During preparations for a targeted alerting customer demo, an urgent need gave me an opportunity to put it into practice.

Developers wouldn’t have time to implement the recipient-facing LiveLink I had designed, so I volunteered to implement the designs myself. I directed AI to build it in the product codebase and checked the behaviour locally. Our web developer reviewed the code and made last-minute fixes before it was merged and included in the targeted alerting capability delivered for the customer demo.

Establishing a reusable approach

After the pilot, I came across Alpha Design Partners’ AI-native design maturity framework. It helped me turn the initial goal into an AI design maturity initiative, with the prototyping workflow as one part.

I aligned Figma variables with code tokens and added repository guidance for coding agents. These shared rules support NSC3 web development as well as prototypes.

I established a dedicated prototyping environment within the development codebase, using actual components, fictional data and simulated services.

Planning and tracking the initiative

I use the tracker to assess our progress and decide what to work on next.

I also adapted the framework to how our team works. I removed a proposed requirement for separate designer approval of routine UI changes. I trust our developers to implement the designs we have reviewed, and we discuss changes when the designs leave something open.

How I use the workflow

I design the minimum UI needed for the feature in Figma, then direct AI to build an interactive code prototype. There I add states, interactions and responsiveness, and demonstrate the flows. I apply design-review feedback directly to the prototype so the team can try the revised behaviour. Developers can then review and adapt the code for implementation.

Solution

The workflow in practice: event image viewer.

I used the workflow to design an event image viewer for NSC3. Operators needed to examine images associated with an event while keeping its details and navigation between images available.

I designed the layout in Figma, then worked through zooming, panning and responsiveness in the code prototype. I completed the design and prototype on the same day, then reviewed the interaction with our web developer.

Impact

The targeted alerting capability was handed over to the customer for a two-week demo. It included the recipient-facing LiveLink I had designed and implemented with AI assistance, with developer review and fixes before delivery.

The prototyping environment has since been used for a few features and for design reviews, where we can try the states and flows using the product’s actual components.

Our web developer used the image-viewer prototype code as a starting point for implementation, describing it as mostly usable as is.
